# Refine Section

Iterate on ONE block of an existing landing page generated by `/ordoplugin:create-landing`. Use this when the user wants to tweak (not regenerate) a specific block.

## Step 1 — Locate

1. Read `.claude/ordoplugin.config.json` to find `corpus_path` and `output_target`.
2. Read `marketing/_brief.md`, `marketing/_tokens.json`, `marketing/_plan.md` for context.
3. Identify which block the user wants to refine. If unspecified, list the blocks from `_plan.md` and ask via AskUserQuestion.

## Step 2 — Locate the block in code

Find the section in the generated page file. Common patterns:
- Tailwind/JSX: `<section data-block="hero">` or comment `{/* hero */}`
- Plain HTML: `<section class="hero">`

If the original generation didn't add `data-block` attributes, **add them now** to make refinement deterministic going forward.

## Step 3 — Diagnose

Ask the user one focused AskUserQuestion: what specifically do they want to change? Offer 4 options:

1. **Copy** — change wording / tone / language
2. **Layout** — change structure / order of sub-elements
3. **Visual style** — change palette/spacing/typography for THIS block (carefully — may break consistency)
4. **Replace block type** — swap to a different block from the catalog

## Step 4 — Refine

Apply the change. Constraints:

- **Inherit `_tokens.json`** — never introduce a new color or font-family at the block level. If the user wants a new color, update `_tokens.json` AND propagate to other blocks for consistency.
- **Re-read** the relevant section of [`.claude/ordoplugin-docs/quality-bar.md`](.claude/ordoplugin-docs/quality-bar.md) before writing — easy to drift below the bar when iterating.
- **Preserve reveal animation classes** if present (`.reveal`, etc.)
- **Update `_plan.md`** to reflect the new content of this block.

## Step 5 — Visual check

If `chrome-devtools` MCP is available and the consumer's dev server is running, navigate to the page, screenshot just the affected section, compare against the matched reference's analogous section.

If not running, suggest the user start their dev server, then re-invoke this skill.

## Re-run with same block

If user wants to keep iterating, stay in this skill — make a SHORT next-step ask: "Mais alguma coisa nesse bloco, ou seguimos pra outro?"
